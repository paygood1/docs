title: "Catalog"
---

The Catalog is where a merchant defines **what it sells**. It has two resources:

- **Product**: something you sell, such as "Monthly Giving" or "Zakat Donation".
- **Price**: how much a product costs, either a single charge or a recurring one.

Prices are referenced when creating payments and subscriptions.

## Concepts

### Products

| Field | Type | Description |
| --- | --- | --- |
| `productId` | `string` | Product TypeID (`prod_...`). |
| `merchantId` | `string` | Owning merchant TypeID (`mer_...`). |
| `name` | `string` | Display name. |
| `description` | `string` | Optional description. |
| `status` | `string` | `active` or `inactive`. |
| `active` | `boolean` | `true` when `status` is `active`. |
| `createdAt` | `string` | ISO-8601 timestamp. |

### Prices

| Field | Type | Description |
| --- | --- | --- |
| `priceId` | `string` | Price TypeID (`price_...`). |
| `merchantId` | `string` | Owning merchant TypeID. |
| `productId` | `string` | Optional linked product TypeID. |
| `amount` | `integer` | Amount in minor units (for example, cents). |
| `currency` | `string` | ISO-4217 uppercase code, such as `USD`. |
| `type` | `string` | `one_time` (default) or `recurring`. |
| `interval` | `string` | `day`, `week`, `month` or `year`. For `recurring` prices only. |
| `archivedAt` | `string` | Set once the price is archived. |
| `createdAt` | `string` | ISO-8601 timestamp. |

<Info>
  Prices are immutable. To change what a product costs, archive the old price and create a new one, or use **Update product price**.
</Info>

### Duplicate prevention

Creating a price with the same amount, currency, type, interval and product as an existing **active** price returns that price with `200` instead of creating a duplicate. A new price returns `201`.

## Authentication and conventions

- Authenticate with a bearer token: `Authorization: Bearer <api_key>`.
- Reading requires the `catalog.view` capability. Creating and changing requires `catalog.manage`.
- Every request is scoped to a merchant via `merchantId` (query for reads, body for writes).
- Mutating requests that create resources take an `Idempotency-Key` header. Never send it in the body.
- IDs are TypeIDs minted by the server.
- List endpoints use cursor pagination, newest first.

### Pagination

List endpoints accept `limit` (max 100), `cursor`, and optional `start` and `end` ISO-8601 bounds on `createdAt`.

```json
{
  "items": [],
  "page": { "hasMore": true, "nextCursor": "eyJ2IjoxLC4uLn0=" }
}
```

Pass `page.nextCursor` as `cursor` to fetch the next page.

## Endpoints

### Products

| Method | Path | Summary |
| --- | --- | --- |
| `POST` | `/catalog/products` | Create a product |
| `GET` | `/catalog/products` | List products for a merchant |
| `GET` | `/catalog/products/:productId` | Get a product |
| `PUT` | `/catalog/products/:productId` | Update name and description |
| `PUT` | `/catalog/products/:productId/price` | Replace the product's price |
| `PUT` | `/catalog/products/:productId/status` | Set `active` or `inactive` |

### Prices

| Method | Path | Summary |
| --- | --- | --- |
| `POST` | `/catalog/prices` | Create a price |
| `GET` | `/catalog/prices` | List prices for a merchant |
| `GET` | `/catalog/prices/:priceId` | Get a price |
| `PUT` | `/catalog/prices/:priceId/archive` | Archive a price |

## Quick start

Create a product, then a one-time price linked to it.

```bash
curl -X POST https://api.paygood.co/catalog/products \
  -H "Authorization: Bearer $PAYGOOD_API_KEY" \
  -H "Idempotency-Key: 6f1c2b7e-0d1a-4c52-9a4e-3b1f7a9d2c10" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantId": "mer_01hxy8m1nqk9g3x3y3p0azq2bg",
    "name": "Iced Chai"
  }'
```

```bash
curl -X POST https://api.paygood.co/catalog/prices \
  -H "Authorization: Bearer $PAYGOOD_API_KEY" \
  -H "Idempotency-Key: 0b8e4d1a-7a3f-4c9e-8d52-1e6f9a2b3c47" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantId": "mer_01hxy8m1nqk9g3x3y3p0azq2bg",
    "productId": "prod_01hxy9a2c3d4e5f6g7h8j9k0mn",
    "amount": 700,
    "currency": "USD",
    "type": "one_time"
  }'
```

## Change a product's price

When what you charge for a product changes, use **Update product price**. It swaps the product's current price for a new one in a single step.

```text
PUT /catalog/products/:productId/price
```

### What happens

1. A new price is created for the product and becomes its active price.
2. Every price that was active on the product is archived.

Both happen together. A product is never left with no active price or with two competing ones. Archived prices stay on record, so past payments still point to the amount they were charged.

<Warning>
  This replaces **all** of the product's active prices. If you sell the same product at more than one price, such as a one-time USD 25.00 and a monthly USD 12.00, updating one will archive the other. To add a price without removing the others, use `POST /catalog/prices` instead.
</Warning>

### Request

**Headers**

| Name | Required | Description |
| --- | --- | --- |
| `Authorization` | Yes | `Bearer <api_key>`. The key needs the `catalog.manage` permission. |
| `Idempotency-Key` | Yes | A unique value you generate. Retrying with the same key returns the original result. |

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `merchantId` | `string` | Yes | Your merchant ID (`mer_...`). |
| `amount` | `integer` | Yes | New amount in the smallest currency unit. USD 25.00 is `2500`. |
| `currency` | `string` | Yes | Three-letter uppercase currency code, such as `USD`. |
| `type` | `string` | No | `one_time` (default) or `recurring`. |
| `interval` | `string` | No | `day`, `week`, `month` or `year`. Required when `type` is `recurring`. Leave out |
| for `one_time`. |  |  |  |

### Example: switch to a monthly price

```bash
curl -X PUT https://api.paygood.example/catalog/products/prod_01hxy9a2c3d4e5f6g7h8j9k0mn/price \
  -H "Authorization: Bearer $PAYGOOD_API_KEY" \
  -H "Idempotency-Key: 3d9a7c52-5b1e-4f08-a6c4-8e2b1f0d7a93" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantId": "mer_01hxy8m1nqk9g3x3y3p0azq2bg",
    "amount": 1200,
    "currency": "USD",
    "type": "recurring",
    "interval": "month"
  }'
```

### Response

`200 OK` with the new active price:

```json
{
  "priceId": "price_01hxy9b4d5e6f7g8h9j0k1mnpq",
  "merchantId": "mer_01hxy8m1nqk9g3x3y3p0azq2bg",
  "productId": "prod_01hxy9a2c3d4e5f6g7h8j9k0mn",
  "amount": 1200,
  "currency": "USD",
  "type": "recurring",
  "interval": "month",
  "createdAt": "2026-07-28T20:37:00.000Z"
}
```

Use the new `priceId` for any payment or subscription you create from now on.

### Errors

| Status | When it happens |
| --- | --- |
| `400` | The request is invalid: a bad amount or currency, an unsupported type and interval combination, or the product is **inactive**. |
| `401` | The API key is missing or invalid. |
| `403` | The API key doesn't have the `catalog.manage` permission. |
| `404` | No product with that ID exists on your account. |

<Info>
  An inactive product can't have its price changed. Set it back to `active` first with `PUT /catalog/products/:productId/status`.
</Info>

### Retrying safely

If a request times out and you aren't sure it went through, send it again with the **same** `Idempotency-Key`. You'll get the original response back and the price won't be swapped twice. Use a new key for each new price change.

The 404 row is worded for the merchant because the code returns "Product not found" for both a missing product and a product on another merchant's account. I haven't read the dashboard or merchant-facing error mapping, so I left those out.

## Next steps

Use the returned `priceId` when creating a payment or subscription.

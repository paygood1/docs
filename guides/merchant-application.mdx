---
title: "Submit a Merchant Application via the PayGood API"
sidebarTitle: "Application Walkthrough"
description: "Step-by-step guide to creating, completing, and submitting a merchant KYB application through the PayGood API — from draft to processor approval."
---

This guide walks through the full merchant application process. You'll create a draft application, fill in business details, add owners and payout accounts, and submit for review. Complete each step in order — every request after the first uses the application `id` returned in step 1.

<Steps>

  <Step title="Create a draft application">
    Send a `POST` request to `/merchant-applications` to open a new draft. Include a unique `idempotencyKey` and the merchant's `country` code.

    ```bash
    curl -X POST https://api.paygood.com/merchant-applications \
      -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
      -H 'Content-Type: application/json' \
      -d '{
        "idempotencyKey": "app-create-001",
        "country": "US"
      }'
    ```

    The response contains the new application object. Save the `id` field (e.g., `mapp_01hxy...`) — you'll use it as the path parameter in every subsequent request.

    ```json
    {
      "id": "mapp_01hxy...",
      "country": "US",
      "status": "draft",
      "createdAt": "2024-01-15T10:00:00Z"
    }
    ```

    <Tip>
      If you are creating a sub-merchant under an existing merchant account, pass the parent's ID in the optional `parentMerchantId` field.
    </Tip>
  </Step>

  <Step title="Add business profile">
    Patch the business profile with your merchant's legal and operational details. Replace `{id}` with the application ID from step 1.

    The required fields are `legalName`, `businessType`, `email`, and `registeredAddress` (with `line1`, `city`, and `postalCode`). If the merchant has a tax ID, pass it as a Basis Theory vault token in the `businessTaxId` field.

    ```bash
    curl -X PATCH https://api.paygood.com/merchant-applications/{id}/business-profile \
      -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
      -H 'Content-Type: application/json' \
      -d '{
        "idempotencyKey": "bp-patch-001",
        "businessProfile": {
          "legalName": "Acme Corp",
          "doingBusinessAs": "Acme",
          "businessType": "corporation",
          "email": "contact@acme.com",
          "businessPhone": "+15551234567",
          "website": "https://acme.com",
          "registeredAddress": {
            "line1": "123 Main St",
            "city": "San Francisco",
            "region": "CA",
            "postalCode": "94105",
            "country": "US"
          },
          "businessTaxId": {
            "id": "tok_...",
            "provider": "basistheory"
          },
          "defaultStatementDescriptor": "ACME CORP",
          "mcc": "5999",
          "ownershipType": "private",
          "incorporationDate": { "day": 1, "month": 6, "year": 2018 }
        }
      }'
    ```

    Use the following values for the `businessType` field:

    | Value | Description |
    |-------|-------------|
    | `individual_sole_proprietorship` | Sole proprietorship or single-person business |
    | `corporation` | C-corp or S-corp |
    | `limited_liability_company` | LLC |
    | `partnership` | General or limited partnership |
    | `non_profit` | Non-profit organization |
    | `government` | Government entity |
  </Step>

  <Step title="Add beneficial owners">
    Provide identity information for every individual who owns more than 25% of the business. Include all qualifying owners in a single request.

    ```bash
    curl -X PATCH https://api.paygood.com/merchant-applications/{id}/beneficial-owners \
      -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
      -H 'Content-Type: application/json' \
      -d '{
        "idempotencyKey": "bo-patch-001",
        "beneficialOwners": [
          {
            "firstName": "Jane",
            "lastName": "Smith",
            "dateOfBirth": { "day": 15, "month": 3, "year": 1985 },
            "ownershipPercent": 51,
            "title": "CEO",
            "personalAddress": {
              "line1": "456 Oak Ave",
              "city": "San Francisco",
              "region": "CA",
              "postalCode": "94102",
              "country": "US"
            },
            "email": "jane@acme.com",
            "phone": "+15551234567",
            "taxId": {
              "id": "tok_...",
              "provider": "basistheory"
            }
          }
        ]
      }'
    ```

    The `taxId` field accepts a vault token object rather than a raw tax ID number. Tokenize the value with Basis Theory first, then pass the resulting token: `{"id": "tok_...", "provider": "basistheory"}`.

    <Warning>
      This operation **replaces all beneficial owners** on the application. Pass the complete list of owners in a single request — any owners omitted from the array will be removed.
    </Warning>
  </Step>

  <Step title="Add payout accounts">
    Link the bank account where PayGood will settle funds for the merchant. Bank account details must be sent as a Basis Theory vault token rather than raw account numbers.

    ```bash
    curl -X PATCH https://api.paygood.com/merchant-applications/{id}/payout-accounts \
      -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
      -H 'Content-Type: application/json' \
      -d '{
        "idempotencyKey": "pa-patch-001",
        "payoutAccounts": [
          {
            "accountType": "business",
            "accountHolderName": "Acme Corp",
            "vaultToken": {
              "id": "tok_...",
              "provider": "basistheory"
            }
          }
        ]
      }'
    ```

    Vault the bank account number and routing number with Basis Theory before calling this endpoint, then pass the returned token in the `vaultToken` field.

    <Warning>
      This operation **replaces all payout accounts** on the application. Pass the complete list of accounts in one call — any accounts omitted from the array will be removed.
    </Warning>
  </Step>

  <Step title="Add underwriting data">
    Supply processing volume estimates and a description of the merchant's business. PayGood's underwriting team uses this information during the review process.

    ```bash
    curl -X PATCH https://api.paygood.com/merchant-applications/{id}/underwriting \
      -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
      -H 'Content-Type: application/json' \
      -d '{
        "idempotencyKey": "uw-patch-001",
        "underwritingData": {
          "averageCardTransferAmount": 7500,
          "averageAchTransferAmount": 0,
          "annualAchVolume": 0,
          "businessDescription": "Online retail store selling home goods",
          "cardVolumeDistribution": {
            "cardPresentPercent": 0,
            "ecommercePercent": 100,
            "mailOrderTelephonePercent": 0
          },
          "refundPolicy": "30-day returns"
        }
      }'
    ```

    The three values in `cardVolumeDistribution` — `cardPresentPercent`, `ecommercePercent`, and `mailOrderTelephonePercent` — must add up to exactly `100`. Amounts are expressed in the smallest currency unit (e.g., cents for USD).
  </Step>

  <Step title="Submit for review">
    Once all sections are complete, submit the application to PayGood's underwriting team for review.

    ```bash
    curl -X POST https://api.paygood.com/merchant-applications/{id}/submit \
      -H 'Authorization: Bearer $PAYGOOD_API_KEY'
    ```

    Submitting the application locks the data and sends it to our payment processor for KYB review. The review timeline varies based on the business type and the information provided. You'll be notified when a decision is made.

    <Info>
      After submission, check the current status of the application at any time by calling `GET /merchant-applications/{id}`. The `status` field reflects where the application is in the review process.
    </Info>
  </Step>

</Steps>

<Tip>
  Use a unique `idempotencyKey` on every `POST` and `PATCH` request. If a request fails or times out, you can safely retry it with the same key — PayGood will return the original response without creating duplicates or applying the change twice.
</Tip>

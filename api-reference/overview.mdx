The PayGood API is a REST API that uses JSON for request and response bodies. All requests must be authenticated with your API key. You interact with the API by sending HTTP requests to resource endpoints and parsing the JSON responses.

## Base URL

All API requests are made to the following base URL:

```
https://api.paygood.com
```

## Request format

For all `POST`, `PATCH`, and `PUT` requests, include the `Content-Type: application/json` header and send a JSON-encoded request body.

```bash
curl https://api.paygood.com/payments \
  -X POST \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{ "amount": 1000, "currency": "USD" }'
```

## Core concepts

Before making your first request, familiarize yourself with three topics that apply across all endpoints:

- **[Authentication](/api-reference/authentication)** — Every request must include a Bearer token in the `Authorization` header. PayGood issues separate keys for production and sandbox environments.
- **[Pagination](/api-reference/pagination)** — List endpoints return results in cursor-based pages. Use the `page.nextCursor` value from each response to fetch the next page.
- **[Errors](/api-reference/errors)** — Errors are returned as standard HTTP status codes with a JSON body that includes a human-readable `message` field.

## Idempotency

Write operations (`POST`, `PATCH`, `PUT`) accept an `idempotencyKey` field in the request body. Set this to a unique, client-generated string — such as a UUID — before sending the request.

```json
{
  "idempotencyKey": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "amount": 1000,
  "currency": "USD"
}
```

If your request fails due to a network timeout or other transient error, resend the exact same request body with the same `idempotencyKey`. The server recognizes the key and returns the original response without creating a duplicate resource. This makes it safe to retry any write operation without risking double-charges or duplicate records.

<Note>
  Idempotency keys are scoped to your API key and expire after 24 hours. Use a fresh key for each logically distinct operation.
</Note>

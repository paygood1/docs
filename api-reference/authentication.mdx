title: "How to Authenticate Requests to the PayGood API"
sidebarTitle: "Authentication"

---

PayGood uses API keys as Bearer tokens to authenticate every request. Include your key in the `Authorization` header of every request you send to the API. Requests made without a valid key are rejected with a `401 Unauthorized` response.

## Authorization header

Pass your API key as a Bearer token in the `Authorization` header:

```
Authorization: Bearer YOUR_API_KEY
```

Here is a complete example using `curl`:

```bash
curl https://api.paygood.com/payments \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json'
```

## Key types

PayGood issues two types of API keys. Use sandbox keys during development so you never affect live payment data.

| Key Type   | Use                      |
|------------|--------------------------|
| Production | Live payments            |
| Sandbox    | Testing and development  |

<Info>
  Sandbox keys have access to the same endpoints as production keys, but all operations are simulated and no real money moves.
</Info>

## Error responses

If you omit the `Authorization` header or supply an invalid key, the API returns a `401 Unauthorized` response:

```json
{
  "statusCode": 401,
  "message": "Unauthorized"
}
```

Check the following if you receive this error:

- Confirm the `Authorization` header is present on the request.
- Verify you are using the correct key type for the environment (production vs. sandbox).
- Ensure the key has not been revoked in your dashboard.

<Warning>
  Never include API keys in client-side code, git repositories, or log files. If a key is exposed, rotate it immediately from the PayGood dashboard.
</Warning>

See [Managing API keys](/guides/api-keys) for instructions on creating, rotating, and revoking keys.

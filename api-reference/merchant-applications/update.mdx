After creating a draft application, use these PATCH endpoints to fill in the required business details, beneficial owners, payout accounts, and underwriting data before submitting for review. Each endpoint targets a specific section of the application and can be called in any order.

<Note>
  Each PATCH endpoint replaces the **full data** for that section. Always send the complete updated payload, not a partial update.
</Note>

---

## Business profile

`PATCH https://api.paygood.com/merchant-applications/{id}/business-profile`

Use this endpoint to provide or update the merchant's legal business details.

### Path parameters

<ParamField path="id" type="string" required>
  The application ID returned when you [created the draft](/api-reference/merchant-applications/create).
</ParamField>

### Request body parameters

<ParamField body="idempotencyKey" type="string" required>
  A unique key for this request. Retrying with the same key returns the original response without re-applying the update.
</ParamField>

<ParamField body="businessProfile" type="object" required>
  Object containing the merchant's full business profile.

  <Expandable title="businessProfile fields">
    <ParamField body="legalName" type="string" required>
      The legal registered name of the business.
    </ParamField>

    <ParamField body="businessType" type="string" required>
      Legal entity type. One of: `individual_sole_proprietorship`, `corporation`, `limited_liability_company`, `partnership`, `non_profit`, `government`.
    </ParamField>

    <ParamField body="email" type="string" required>
      Primary business contact email address.
    </ParamField>

    <ParamField body="registeredAddress" type="object" required>
      The legal registered address of the business.

      <Expandable title="registeredAddress fields">
        <ParamField body="line1" type="string" required>
          Street address line 1.
        </ParamField>

        <ParamField body="line2" type="string">
          Street address line 2 (suite, unit, etc.).
        </ParamField>

        <ParamField body="city" type="string" required>
          City name.
        </ParamField>

        <ParamField body="region" type="string">
          State or province code (e.g. `CA`).
        </ParamField>

        <ParamField body="postalCode" type="string" required>
          ZIP or postal code.
        </ParamField>

        <ParamField body="country" type="string">
          ISO 3166-1 alpha-2 country code (e.g. `US`).
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="doingBusinessAs" type="string">
      Trade name or DBA if different from `legalName`.
    </ParamField>

    <ParamField body="businessPhone" type="string">
      Business phone number in E.164 format (e.g. `+15551234567`).
    </ParamField>

    <ParamField body="website" type="string">
      The merchant's public-facing website URL.
    </ParamField>

    <ParamField body="defaultStatementDescriptor" type="string">
      Text that appears on customer card statements. Typically the business name in uppercase.
    </ParamField>

    <ParamField body="mcc" type="string">
      Merchant Category Code (ISO 18245) representing the business's primary industry.
    </ParamField>

    <ParamField body="ownershipType" type="string">
      Indicates whether the company is `public` or `private`.
    </ParamField>

    <ParamField body="annualCardVolume" type="object">
      Projected annual card processing volume. Contains `amount` (integer, in smallest currency unit — cents for USD/CAD) and `currency` (ISO 4217 code, e.g. `USD`).
    </ParamField>

    <ParamField body="maxTransactionAmount" type="object">
      Maximum expected single card transaction amount. Contains `amount` (integer, in cents) and `currency`.
    </ParamField>

    <ParamField body="achMaxTransactionAmount" type="object">
      Maximum expected single ACH transaction amount. Contains `amount` (integer, in cents) and `currency`.
    </ParamField>

    <ParamField body="businessTaxId" type="object">
      Vault token representing the business's tax ID (EIN). Use Basis Theory to tokenize the raw value before sending. Format: `{"id": "...", "provider": "basistheory"}`.
    </ParamField>

    <ParamField body="hasAcceptedCreditCardsPreviously" type="boolean">
      Set to `true` if the merchant has previously processed credit card payments.
    </ParamField>

    <ParamField body="incorporationDate" type="object">
      Date the business was incorporated. Contains `day`, `month`, and `year` as integers.
    </ParamField>
  </Expandable>
</ParamField>

### Example request

```bash
curl -X PATCH https://api.paygood.com/merchant-applications/mapp_01hxy4k2e3f5g6h7j8k9m0n1p/business-profile \
  -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotencyKey": "bp-001",
    "businessProfile": {
      "legalName": "Acme Corp",
      "doingBusinessAs": "Acme",
      "businessType": "corporation",
      "businessTaxId": { "id": "tok_basistheory_ein_abc", "provider": "basistheory" },
      "email": "contact@acme.com",
      "businessPhone": "+15551234567",
      "website": "https://acme.com",
      "registeredAddress": {
        "line1": "123 Main St",
        "city": "San Francisco",
        "region": "CA",
        "postalCode": "94105",
        "country": "US"
      },
      "defaultStatementDescriptor": "ACME CORP",
      "mcc": "5999",
      "ownershipType": "private",
      "annualCardVolume": { "amount": 500000, "currency": "USD" },
      "maxTransactionAmount": { "amount": 10000, "currency": "USD" },
      "achMaxTransactionAmount": { "amount": 5000, "currency": "USD" },
      "hasAcceptedCreditCardsPreviously": true,
      "incorporationDate": { "day": 1, "month": 6, "year": 2018 }
    }
  }'
```

## Beneficial owners

`PATCH https://api.paygood.com/merchant-applications/{id}/beneficial-owners`

Provide details for all individuals who directly or indirectly own 25% or more of the business. This information is required for KYB compliance.

<Warning>
  This endpoint **replaces all** existing beneficial owners on the application. Every call must include the complete list of owners — including any owners you are not changing. Omitting an owner will remove them from the application.
</Warning>

### Path parameters

<ParamField path="id" type="string" required>
  The application ID returned when you [created the draft](/api-reference/merchant-applications/create).
</ParamField>

### Request body parameters

<ParamField body="idempotencyKey" type="string" required>
  A unique key for this request.
</ParamField>

<ParamField body="beneficialOwners" type="array" required>
  Array of beneficial owner objects. Each object represents one individual owner.

  <Expandable title="beneficialOwner fields">
    <ParamField body="firstName" type="string" required>
      Owner's legal first name.
    </ParamField>

    <ParamField body="lastName" type="string" required>
      Owner's legal last name.
    </ParamField>

    <ParamField body="dateOfBirth" type="object" required>
      Owner's date of birth. Contains `day`, `month`, and `year` as integers.
    </ParamField>

    <ParamField body="ownershipPercent" type="number" required>
      Percentage of the business owned by this individual (0–100).
    </ParamField>

    <ParamField body="title" type="string">
      Owner's job title (e.g. `CEO`, `CFO`).
    </ParamField>

    <ParamField body="personalAddress" type="object">
      Owner's personal residential address. Uses the same shape as `registeredAddress`: `line1`, `line2`, `city`, `region`, `postalCode`, `country`.
    </ParamField>

    <ParamField body="taxId" type="object">
      Vault token representing the owner's government-issued tax ID (SSN/SIN). Format: `{"id": "...", "provider": "basistheory"}`.
    </ParamField>

    <ParamField body="email" type="string">
      Owner's personal email address.
    </ParamField>

    <ParamField body="phone" type="string">
      Owner's personal phone number in E.164 format.
    </ParamField>
  </Expandable>
</ParamField>

### Example request

```bash
curl -X PATCH https://api.paygood.com/merchant-applications/mapp_01hxy4k2e3f5g6h7j8k9m0n1p/beneficial-owners \
  -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotencyKey": "bo-001",
    "beneficialOwners": [
      {
        "firstName": "Jane",
        "lastName": "Smith",
        "dateOfBirth": { "day": 15, "month": 3, "year": 1985 },
        "ownershipPercent": 51,
        "title": "CEO",
        "personalAddress": {
          "line1": "456 Oak Ave",
          "city": "San Francisco",
          "region": "CA",
          "postalCode": "94102",
          "country": "US"
        },
        "taxId": { "id": "tok_basistheory_ssn_abc", "provider": "basistheory" },
        "phone": "+15551234567",
        "email": "jane@acme.com"
      }
    ]
  }'
```

## Payout accounts

`PATCH https://api.paygood.com/merchant-applications/{id}/payout-accounts`

Specify the bank account(s) where the merchant will receive payouts.

<Warning>
  This endpoint **replaces all** existing payout accounts on the application. Every call must include the complete list of accounts — including any accounts you are not changing. Omitting an account will remove it from the application.
</Warning>

### Path parameters

<ParamField path="id" type="string" required>
  The application ID returned when you [created the draft](/api-reference/merchant-applications/create).
</ParamField>

### Request body parameters

<ParamField body="idempotencyKey" type="string" required>
  A unique key for this request.
</ParamField>

<ParamField body="payoutAccounts" type="array" required>
  Array of payout account objects.

  <Expandable title="payoutAccount fields">
    <ParamField body="accountType" type="string" required>
      Whether the account belongs to the business or an individual owner. One of: `personal`, `business`.
    </ParamField>

    <ParamField body="accountHolderName" type="string" required>
      Full name of the account holder as it appears on the bank account.
    </ParamField>

    <ParamField body="vaultToken" type="object" required>
      Basis Theory vault token representing the bank account details (routing number, account number). Format: `{"id": "...", "provider": "basistheory"}`.
    </ParamField>

    <ParamField body="currency" type="string">
      ISO 4217 currency code for this payout account (e.g. `USD`).
    </ParamField>
  </Expandable>
</ParamField>

### Example request

```bash
curl -X PATCH https://api.paygood.com/merchant-applications/mapp_01hxy4k2e3f5g6h7j8k9m0n1p/payout-accounts \
  -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotencyKey": "pa-001",
    "payoutAccounts": [
      {
        "accountType": "business",
        "accountHolderName": "Acme Corp",
        "vaultToken": { "id": "tok_basistheory_bank_abc", "provider": "basistheory" },
        "currency": "USD"
      }
    ]
  }'
```

## Underwriting data

`PATCH https://api.paygood.com/merchant-applications/{id}/underwriting`

Provide transaction volume estimates and business details used during the underwriting review.

### Path parameters

<ParamField path="id" type="string" required>
  The application ID returned when you [created the draft](/api-reference/merchant-applications/create).
</ParamField>

### Request body parameters

<ParamField body="idempotencyKey" type="string" required>
  A unique key for this request.
</ParamField>

<ParamField body="underwritingData" type="object" required>
  Object containing underwriting details.

  <Expandable title="underwritingData fields">
    <ParamField body="averageCardTransferAmount" type="number">
      Expected average card transaction amount in the smallest currency unit (e.g. cents for USD/CAD).
    </ParamField>

    <ParamField body="businessDescription" type="string">
      Short description of what the business sells or the services it provides.
    </ParamField>

    <ParamField body="cardVolumeDistribution" type="object">
      Breakdown of how card transactions will be accepted. The three percentage fields must sum to exactly `100`.

      <Expandable title="cardVolumeDistribution fields">
        <ParamField body="cardPresentPercent" type="number">
          Percentage of transactions processed in-person (card-present).
        </ParamField>

        <ParamField body="ecommercePercent" type="number">
          Percentage of transactions processed online (e-commerce).
        </ParamField>

        <ParamField body="mailOrderTelephonePercent" type="number">
          Percentage of transactions taken via mail order or telephone (MOTO).
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="refundPolicy" type="string">
      Description of the merchant's customer refund or return policy.
    </ParamField>
  </Expandable>
</ParamField>

### Example request

```bash
curl -X PATCH https://api.paygood.com/merchant-applications/mapp_01hxy4k2e3f5g6h7j8k9m0n1p/underwriting \
  -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotencyKey": "uw-001",
    "underwritingData": {
      "averageCardTransferAmount": 7500,
      "businessDescription": "Online retail store selling home goods",
      "cardVolumeDistribution": {
        "cardPresentPercent": 0,
        "ecommercePercent": 100,
        "mailOrderTelephonePercent": 0
      },
      "refundPolicy": "30-day returns"
    }
  }'
```

---

<Tip>
  Use a unique `idempotencyKey` for each PATCH call so retries are safe. If a request fails mid-flight, you can retry with the same key without risk of applying the update twice.
</Tip>

Once all four sections are complete, you're ready to submit. See [Submit Application](/api-reference/merchant-applications/submit) for the next step.

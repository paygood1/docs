---
title: "Create a Platform Customer — PayGood Customers API"
sidebarTitle: "Create Customer"
description: "Create a new customer record in PayGood for an individual or business. Supports idempotent creation to prevent duplicate records across retries."
---

`POST /customers` creates a new platform-level customer record in PayGood. Customers represent the individuals or businesses you collect payments from. If you want to associate a customer directly with a specific merchant at creation time, you can also create merchant-scoped customers at `POST /merchants/{merchantId}/customers` — see [Merchant-scoped customers](#merchant-scoped-customers) below.

```
POST https://api.paygood.com/customers
```

## Request body

<ParamField body="idempotencyKey" type="string" required>
  A unique key you generate for this customer creation request. Retrying with the same key returns the original response and prevents duplicate records from being created.
</ParamField>

<ParamField body="name" type="string" required>
  The full name of the customer or business.
</ParamField>

<ParamField body="email" type="string" required>
  A valid email address for the customer. Used for receipts and notifications.
</ParamField>

<ParamField body="entityType" type="string" required>
  The type of entity this customer represents. Must be either `individual` (for a person) or `business` (for a company or organization).
</ParamField>

<ParamField body="phone" type="string">
  The customer's phone number. E.164 format is recommended (e.g., `+15551234567`).
</ParamField>

<Note>
  Use `entityType: "business"` for companies and organizations, and `entityType: "individual"` for people. This value affects how the customer is treated in downstream compliance and reporting workflows.
</Note>

## Request example

```bash
curl -X POST https://api.paygood.com/customers \
  -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotencyKey": "cust-001",
    "name": "Jane Smith",
    "email": "jane@example.com",
    "entityType": "individual",
    "phone": "+15551234567"
  }'
```

## Response fields

<ResponseField name="customerId" type="string">
  The unique TypeID assigned to this customer (`cus_...`).
</ResponseField>

<ResponseField name="name" type="string">
  The full name of the customer.
</ResponseField>

<ResponseField name="email" type="string">
  The email address on file for this customer.
</ResponseField>

<ResponseField name="entityType" type="string">
  The entity type: `individual` or `business`.
</ResponseField>

<ResponseField name="phone" type="string">
  The customer's phone number, if one was provided.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO-8601 timestamp of when the customer record was created.
</ResponseField>

## Response example

```json
{
  "customerId": "cus_01hxy8m1nqk9g3x3y3p0azq2bg",
  "name": "Jane Smith",
  "email": "jane@example.com",
  "entityType": "individual",
  "phone": "+15551234567",
  "createdAt": "2026-03-15T10:00:00.000Z"
}
```

## Merchant-scoped customers

If you need to create a customer that is immediately linked to a specific merchant, use `POST /merchants/{merchantId}/customers` instead. This endpoint accepts the same request body fields as `POST /customers` and returns the same customer fields, but the customer is automatically associated with the merchant on creation.

```bash
curl -X POST https://api.paygood.com/merchants/mer_01hxy8m1nqk9g3x3y3p0azq2bg/customers \
  -H 'Authorization: Bearer $PAYGOOD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotencyKey": "cust-merchant-001",
    "name": "Jane Smith",
    "email": "jane@example.com",
    "entityType": "individual",
    "phone": "+15551234567"
  }'
```

You can retrieve all customers linked to a merchant using [`GET /merchants/{merchantId}/customers`](/api-reference/customers/list-merchant-customers).

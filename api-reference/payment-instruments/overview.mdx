A payment instrument is a tokenized card or bank account linked to a customer record in PayGood. PayGood never handles raw card or account data — instruments are built on vault tokens from [Basis Theory](https://basistheory.com), so your integration stays entirely out of PCI scope and your customers' sensitive data is never transmitted through your servers.

## Instrument types

PayGood supports two instrument types. Both are registered the same way and produce a `paymentInstrumentId` you can reference in payment requests.

| Type | Description | Examples |
|---|---|---|
| `card` | A tokenized debit or credit card | Visa, Mastercard, Amex, Discover |
| `bank_account` | A tokenized bank account for ACH, EFT, or IBAN payments | ACH (US), EFT (CA), BACS (GB), IBAN (EU) |

## Instrument lifecycle

Every instrument moves through a set of statuses from the moment it is registered until it is no longer usable.

| Status | Meaning |
|---|---|
| `pending` | The instrument has been registered and is being verified or set up |
| `active` | The instrument is ready to use in payment requests |
| `failed` | Setup could not be completed — the instrument cannot be charged |
| `disabled` | The instrument has been deactivated and can no longer be used |

Only instruments with an `active` status can be used to create payments. Poll or listen for status updates before attempting to charge a newly registered instrument.

## How to use instruments

Registering and using a payment instrument follows a three-step flow:

1. **Tokenize sensitive data with Basis Theory.** Collect your customer's card or bank account details using Basis Theory's secure elements or vault APIs. Basis Theory returns a `vaultToken` containing a token `id` and the provider name `basistheory`. Raw card or account numbers never touch your server.

2. **Register the instrument with PayGood.** Send the vault token along with the `customerId` and `merchantId` to `POST /payment-instruments`. PayGood resolves the token with Basis Theory, populates masked display details, and returns a `paymentInstrumentId`.

3. **Use the `paymentInstrumentId` in payments.** Reference the returned `paymentInstrumentId` when creating a payment. PayGood handles all downstream token resolution — you never need to pass raw card data again.
